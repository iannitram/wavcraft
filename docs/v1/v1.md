# WavCraft v1: the feature list

> **Copied into the repo 2026-10-26** from the pre-GitHub design archive so this repo is self-contained (pipeline v2, R01). This is the v1 scope I approved on 2026-10-15. Issues for anything not on this list are labelled `after-1.0` (my ruling, 2026-10-25). Companion docs sit next to this file.

*Written 2026-10-15 by the WavCraft design session (laptop). **Approved by me the same day, with changes** (my answers are in [questions-and-answers.md](questions-and-answers.md)): MP3 export is required, third-party plugins are out, recording is in, and v1 has to run on Lani's 8 GB Mac, so long files are read from disk and never loaded whole.*

**What v1 is:** Audition's **Waveform Editor**, rebuilt for podcast cleanup. You open one file, see it as a waveform and a spectrogram, select a piece, fix it, check the loudness and save. It is done when I can clean a real podcast episode from start to finish in WavCraft and would rather use it than what I use now, judged by Lani's ears and mine (app.md, Phase 3).

**Names:** the menus, panels and effects use Audition's names. I know Audition, so an Audition name is one less thing to look for. How each one behaves is in [audition-behaviour.md](audition-behaviour.md); the build is in [architecture.md](architecture.md).

**How to read "Done":** each item says what has to be true before it counts. Something "measured" needs a number written in the task's report. Something "by ear" needs Lani or me to have listened.

## Already working (Phase 1, on Hyperion, 2026-10-12)

The app opens a file on a worker thread and shows a time ruler, a waveform lane and a spectrogram lane for each channel. You can zoom with the wheel around the pointer, scroll, click to place the cursor, drag a time selection, and press Space to play with a moving playhead. The far-zoom spectrogram comes from a cached overview. There are 30 tests and clippy is clean. Several fixed interactions have still not been tried by hand, and no real episode has been opened yet.

## In v1

### A. Files

| # | Feature (Audition name) | Done looks like |
|---|---|---|
| A1 | **Open** WAV (16/24/32-bit int, 32-bit float, BWF, RF64), AIFF, MP3, and FLAC. Opening streams the file into the session's on-disk store ([architecture.md](architecture.md)) and never holds it whole in RAM | Each format opens and its duration, sample rate and channel count match a reference tool. A 3-hour 48 kHz stereo WAV opens in under 10 s on Hyperion, and opening adds no more than 300 MB of memory (both measured). **No length limit** apart from disk space: the old ~3 h 06 min limit is gone. Opening can be cancelled |
| A2 | **Save** (Ctrl+S) back to the same format, and **Save As** (Ctrl+Shift+S) to WAV, AIFF or FLAC | Open a file, save it unedited, and the samples come back bit-identical for 16/24-bit int and 32-bit float WAV and AIFF (a test checks each). Saving writes to a temporary file and then swaps it in, so a crash mid-save leaves the original whole. The title bar shows `*` while there are unsaved changes, and closing with unsaved changes asks first |
| A3 | **Save As MP3**: CBR, mono or stereo. **Default 192 kbps CBR**, as in Audition; its list runs 16–320 kbps, and the low rates resample to 8–32 kHz *(checked in Audition 26.5.0.82, 2026-10-15)*. v1 offers 32–320 kbps at 32/44.1/48 kHz (the encoder brief's scope); the lower ones come with MPEG-2 later. The bit-rate test for speech stays at 128 kbps mono. **Required for v1** (my decision, 2026-10-15): v1 isn't done without it. The encoder is our own pure-Rust MIT/Apache crate, shared with SoundCraft and built on the Z13 ([tasks/mp3-encoder-brief.md](tasks/mp3-encoder-brief.md)). WavCraft calls it | A 1-hour episode exports, plays in Apple Podcasts' validator and in a browser, and Lani and I can't tell it from the WAV at 128 kbps mono speech by ear |
| A4 | **Convert Sample Type** (Shift+T †, F11 †) and the sample type in Save As: change bit depth (32-bit float to 16/24-bit), with Dithering a checkbox, Dither Type (Triangular is the type offered first) and Noise Shaping (None). **Dithering is off by default, as in Audition** *(checked in Audition 26.5.0.82, 2026-10-15)*. That also keeps our save bit-exact for untouched audio. Turning it on is remembered | With dither on, converting a −90 dBFS sine to 16 bits gives noise, not stepped distortion (measured on a spectrum). With it off, conversion is plain rounding, and a 16-bit file saved back as 16-bit is bit-identical |
| A5 | **Files panel:** the open files, with sample rate, channels, length and an unsaved-changes mark. Click one to show it | Two files open at once; switching between them keeps each one's zoom, selection and undo history |
| A6 | **Markers survive a save:** markers are written into the WAV (cue points and their labels) and read back on open | Save with 5 markers, reopen, and all 5 are back at the same sample with the same names. Audition reads them back too (I check one file on a machine that has Audition, if I still have one) |

### D. Editing (destructive, as in Audition's Waveform Editor)

| # | Feature | Done looks like |
|---|---|---|
| D1 | **Cut / Copy / Paste / Delete** (Ctrl+X/C/V, Delete) on a time selection | Cutting an hour out of the middle of a 3-hour file takes under 50 ms and uses no extra sample memory (measured). Paste puts the clipboard at the cursor or over the selection |
| D2 | **Copy to New / Paste to New** | Makes a new untitled file in the Files panel |
| D3 | **Silence** (replaces the selection with silence, same length) and **Insert Silence** (a set length at the cursor) | Bit-exact zeros; length unchanged or exactly longer |
| D4 | **Crop / Trim to selection** (Ctrl+T) | Only the selection remains |
| D5 | **Undo / Redo** (Ctrl+Z / Ctrl+Shift+Z) for every edit and effect, the menu items naming the step ("Undo Delete"), and a **History panel** listing each step that you can click to go back to (Up/Down arrows step through it). Clear History in the panel menu. History ends when the file is closed, as in Audition | 200 steps in a row on a 3-hour file, then undo all of them: the samples are bit-identical to the opened file (a test checks this). An undo of a cut takes under 50 ms. Audition calls its undo unlimited. Ours is capped by disk space (default in [architecture.md](architecture.md)), and the oldest steps drop off with a notice, never silently mid-step |
| D7 | **Edit crossfades**, two preferences as in Audition's Preferences > Data, both on by default: "Smooth delete/cut boundaries with crossfades of **2 ms**" and "Smooth all edit boundaries by crossfading **5 ms**" (paste, silence and effect edges) *(checked in Audition 26.5.0.82, 2026-10-15)* | A cut, a paste, a silence and an effect inside a full-scale 1 kHz sine leave no click (no sample-to-sample jump bigger than the sine's own, measured). With both at 0, splices are exact |
| D6 | **Zero-crossing adjust** of selection edges (Audition: Edit > Zero Crossings) | Edges land on the nearest sign change within 10 ms |

## Deliberately not in v1

| Out | Why, and when |
|---|---|
| **Multitrack** | A later phase of WavCraft itself, with its own multitrack built on our own document model. **Never SoundCraft's UI**, and no switcher into SoundCraft (dropped 2026-10-15) |
| Spot Healing Brush and spectral auto-heal | Big DSP job; app.md parks it after v1. A spectral marquee + Amplify (C4) or Silence covers the simple cases until then |
| Adaptive Noise Reduction, DeNoise, Hiss Reduction, DeHummer, Click/Pop Eliminator, DeClipper | After v1. Noise-print reduction comes first because it's the one my cleanup is built round. DeHummer is the next candidate if my rooms hum |
| AI speech enhancement (Lani's "Enhance Speech" request, DeepFilterNet) | A v1.x feature. It needs its own licence check of the model weights first |
| Batch processing, Match Loudness on a list of files | After v1. In v1 Match Loudness works on the open file |
| Video, CD burning, Diagnostics panel, Essential Sound panel, frequency analysis panel, phase meter | Not used for podcast cleanup |
| AAC/M4A, OGG, Opus export | After MP3. Read-only where `audio-io` already reads them |
| Mix Paste (overlap, modulate, loop paste), Gain HUD, Gain/Fade Envelope lines, Hard Limiter as a one-shot | After v1. Paste, Amplify and the fade handles cover the cleanup |
| Audition's other restoration tools (Sound Remover, DeReverb, Automatic Click Remover) | After v1, with the others above |
| Editing while playing in a loop, live effects on playback | Preview in effect dialogs (E6) covers it |
| Third-party plugins (CLAP / VST3) in the Effects Rack | I use none (2026-10-15). SoundCraft's `clap-host` / `vst3-host` stay available for later |
| Recording from several mics at once, punch-in, monitoring through WavCraft, recording into an existing file | v1 records one mic into a new file. Multi-mic recording belongs with Multitrack |
| GPU spectrogram (Track B, B3) | Only if measurements show the CPU picture is too slow on the Z13 |

## Order of the work

1. **Phase 2, Editor** (tasks 01–08 in [tasks/](tasks/)): A1 (streamed open), A2, D1, D3, D4, D5, D7 and I7 with the store and edit model underneath, C1–C3, C5, H1–H4, A6. **Done when** a full rough-cut edit of an episode is saved, reopened, and is identical (app.md).
2. **Recording** (tasks 09–11): J1–J7. **Done when** I record a real 10-minute take on each machine, kill the app once mid-take, and get everything back.
3. **Phase 3, Repair**: E1–E6, G4, G3, G1–G2, F1–F3, then A4. **Done when** I clean a real episode end to end and prefer the result to my current tool's, by ear.
4. **Phase 4, Feel**: B3–B5, C4, C6, I1–I4, A5. **Done when** I work without hunting for things.
5. **Alongside, on the Z13:** the MP3 encoder crate ([tasks/mp3-encoder-brief.md](tasks/mp3-encoder-brief.md)). WavCraft's A3 is wired in once the crate passes its own acceptance.
6. Then the Mac checks (I5, I7, J6: Shuttlecraft 6, then Lani), the notices file (I6), A3 working, and v1 is mine to call.
