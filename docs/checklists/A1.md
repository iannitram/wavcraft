# A1 checklist: reference-tool comparison (ffprobe)

Step A1.5 of the roadmap. A measurement, not a test: ffprobe (the reference tool) and WavCraft are asked the same three questions about each file, and the rows are compared. Every pair should be equal. The one exception allowed is the MP3 row, where encoder padding may change the length, and that row says by how many samples.

Measured on 2026-11-12, at commit `b86c964` on `sat/A1.5-ffprobe-table`, on macOS (Apple silicon). Tools: ffprobe and ffmpeg 9.0.2 from Homebrew (`/opt/homebrew/bin`).

## What is compared

- **Sample rate** in Hz.
- **Channel count**.
- **Duration in samples**: the number of sample frames per channel. ffprobe gives `duration_ts` in units of `time_base`. Samples = `duration_ts` × (numerator / denominator of `time_base`) × `sample_rate`. Every file here has `time_base` 1/`sample_rate`, so `duration_ts` is already in samples, except the MP3 (see its row).

The first four kit rows and the RF64 row are WavCraft's own kit files, and their expected values are the ones `crates/testkit/src/lib.rs` sets in `expected()` (and `HUGE_FRAMES` for the RF64 file). ## ffprobe

The command, run once per file (`FILE` is the path):

```sh
ffprobe -v error -select_streams a:0 -show_entries stream=codec_name,sample_fmt,sample_rate,channels,time_base,duration_ts -of csv=p=0 FILE
```

Output is `codec,sample_fmt,sample_rate,channels,time_base,duration_ts`.

## WavCraft

The values come from the app's control channel, not from a window. Nobody clicked the Files panel tonight, so the rows read the same fields the Files panel shows (`rate`, `channels`, `frames`) through `STATE`:

1. `cargo build --release -j4 -p wavcraft`.
2. Start the app with `WAVCRAFT_CONTROL_PORT=<port>` and `WAVCRAFT_CONTROL_TOKEN_FILE=<file in the kit folder>` (the app creates the token file if it is missing), and `WAVCRAFT_SESSION_DIR=<folder in the kit folder>` so the session store stays out of the home folder.
3. Connect over TCP to `127.0.0.1:<port>`. Send `TOKEN <token file contents>`; the answer is `OK`.
4. For each file, send `OPEN <path>` (the answer is `OK`). Poll `STATE` until `busy=0` and `path=` is that file, then read `rate=`, `channels=` and `frames=`.
5. Quit the app (kill its pid).

`frames=` is sample frames per channel, the same unit as ffprobe's samples.

### The MP3 row

Both tools say 44100 samples per channel (1.000 s at 44.1 kHz), so the difference is 0 samples. The fixture does carry encoder delay: ffprobe puts the stream's `start_time` at 0.025057 s (1105 samples), and the first packet has a `Skip Samples` side-data entry of `skip_samples=1105`. A full ffmpeg decode to raw PCM also gives 176400 bytes = 44100 samples per channel. None of this moves the count in this table.

## Result

Every pair is equal: 0 samples of difference on every row, the MP3 included.
